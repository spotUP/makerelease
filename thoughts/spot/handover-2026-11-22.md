# Handover 2026-11-22 - Amiga Release Packer

Supersedes the rig-hunt part of `handover-2026-11-21.md` (its traps section
still applies). Evidence for everything below: `rig-test-2026-11-21.md`
(Run 1 and Run 2).

## State

- First commit holds the whole port: logic, MUI shell, host tests, fixtures,
  vendored UP-MCC headers. Local repo only, no remote.
- Proven on rig 2 (UP-MCC 1.0, MUI 3.8): window opens; Build writes
  `PROGDIR:releases/<BASE>.LHA` and `<BASE>.ZIP` plus the `<BASE>/` folder;
  Pick... (ASL drawer) puts the drawer inside `<BASE>/` under its own name;
  a failed Build removes `T:rp-<BASE>` (single `build_end:` exit in
  `shell_build()` calling `rp_remove_tree`).
- Fixed this run: NULL `IntuitionBase` at window open (the freeze),
  `PROGDIR:` not valid in the archiver's process (now absolute path),
  `lha` without `-r` dropping `BASE/`.
- Rig 2 stopped with `rig.py stop --keep`. `build/rig2/` (~1.5 GB) is kept
  because another session's debug stream (PID 79090) writes there. A rig
  restart wipes DH0:; reinstall and md5-verify per the 2026-11-21 handover.

## Open, in order

1. `rp_move_dir` copy fallback (staging on another volume) leaves a
   half-copied `PROGDIR:releases/<BASE>` when it fails partway. Remove the
   partial target on failure. Host-testable in `src/stage.c`.
2. `printf` output never reaches the redirect file on a `Run` launch
   (`Run >RAM:packer-out <NIL: ...` only shows `[CLI n]`). Cause unknown.
3. `/X` (X-Innovations) renderer: deliberately phase 2.
4. Report to spot: bare `MUI_NewObject("UP-Cycle.mcc", TAG_DONE)` (no
   `UPA_Cycle_Entries`) hard-freezes the machine. UP-MCC bug.
